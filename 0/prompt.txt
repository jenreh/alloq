Background (from the session that started this one):
While making the alloq planning toolbar toggles (collapse all, density, own projects, own employees) persist per browser, rx.LocalStorage values were wiped after every reload + login. The root cause traced to appkit_user's session filter not exempting Reflex 0.10's `hydrate_and_load`. The alloq planning page now works around it by reading/writing its own localStorage key via rx.call_script (alloq_project/services/planning_view_settings.py), so this fix is about the library and the other pages.

Task:
In appkit_user (installed in the alloq repo at .venv.mac/lib/python3.14/site-packages/appkit_user/authentication/session_filter.py; find the appkit_user source repo first, the venv copy must not be edited), `_bootstrap_events()` exempts `State.hydrate`, but Reflex 0.10's frontend hydrates with `reflex___state____state.hydrate_and_load` (see reflex/state.py `hydrate_and_load` and `.web/utils/context.jsx` `initialEvents`). So on a new tab or after a backend restart, the hydrate event is denied before the client-storage values (session cookie, auth token, rx.LocalStorage vars) reach the backend. The filter then calls `terminate_session()` -> `UserSession.reset()`, drops credentials and redirects to /login. Effects seen in alloq on 2026-10-18: every reload forces a new login, and rx.LocalStorage values of UserSession substates (alloq_projects_view, alloq_team_view, inspector keys) are overwritten with defaults.

Task: add `hydrate_and_load` to the bootstrap events (keep `hydrate`), add a test for it in appkit_user's session-filter tests, and check whether `_prepare_login`'s `terminate_session()` -> `reset()` should leave client-storage vars untouched. Done = appkit_user tests green, and in alloq a reload with a valid session no longer lands on /login (check with the chrome-devtools MCP, isolated context, local test login from memory).
